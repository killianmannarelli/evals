# Micro-PE Rollup Targets — Single-Agent Attempt

## 1. Task Overview

The swarm version would produce `final_report.md`: a consolidated, CIM-style teaser-deck library covering 75 "boring" SMB niches. Each niche section would name 3 specific private acquisition targets meeting tight criteria — **$1M–$5M EBITDA, owner age 55+** — backed by evidence pulled live from state business registries, BuiltWith/Apollo, local news, and industry directories. The deliverable would total ~225 individual teasers, each with CompanyOverview, FinancialSnapshot, OwnershipProfile, InvestmentRationale, and SourceURLs sections, plus an executive summary and table of contents.

## 2. Single-Agent Strategy (Honest Tradeoffs)

With no sub-agents and no live browser, I cannot credibly identify **specific** private SMBs paired with **specific** EBITDA figures and **specific** owner ages — that information lives in state Secretary-of-State filings, LinkedIn, local newspaper retirement-announcement pieces, and paid databases (ZoomInfo, Apollo, Grata, SourceScrub). Training data does not durably memorize private-company financials for ~200 mom-and-pop targets, and inventing names + numbers would be fabrication.

**My adaptation:**
1. Replace 75 niches × 3 named targets with **5 representative "niche sourcing theses"** — each is a CIM-style teaser describing the *archetype* of acquirable target in that niche, not a specific company. Company-specific fields are explicitly marked `UNKNOWN — requires live registry/news search`.
2. Provide a prioritized **coverage gap list of ~70 additional niches** with one-line rationales each, so a downstream operator (or swarm) can pick up the sourcing work.
3. Spend the remaining turns on what a single agent *can* contribute uniquely well: structured niche selection, rationale quality, and a clear handoff document.

Tradeoff: shallower per-entity depth, zero verified live data, but a defensible scaffold a buy-side team or swarm could execute against. I am trading false precision for honest framing.

## 5. Why a Swarm Beats a Single Agent Here

- **Parallel live browsing is the entire job.** Identifying specific $1M–$5M EBITDA, owner-55+ private SMBs requires querying state Secretary-of-State sites, LinkedIn, local newspaper retirement pieces, BuiltWith, and industry directories — *for each candidate*. A swarm of 75 sub-agents browses 75 niches concurrently; a single agent without browse capability cannot do this at all and would have to fabricate names.
- **Per-entity depth requires dedicated context.** Each teaser deck needs 5+ source URLs cross-referenced against 3 different signals (financials, owner age, succession status). 75 agents each holding one niche in context produces far higher-fidelity decks than one agent context-switching across 75 niches and 225 companies.
- **Rate limits and per-source pacing.** Hammering Secretary-of-State sites or LinkedIn from a single thread triggers throttling/blocking; distributed agents with their own sessions are far more resilient (assuming compliant rate-limit policies).
- **Fabrication risk scales nonlinearly for a single agent.** A swarm with live browsing can ground every claim in a URL. A single agent leaning on training knowledge will increasingly hallucinate specific private-company financials and owner identities — exactly the failure mode this task structure surfaces.
- **Coordinator audit pattern is impossible solo.** The swarm design includes a STATUS line audit + gap-fill follow-up wave. A single agent cannot meaningfully audit its own first-pass output or generate independent corroboration — the second-pass review collapses into the same-agent same-context bias.
